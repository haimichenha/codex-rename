# 技术答辩 PPT 的视觉语言与版式规则

## 高级感的来源

高质量技术 PPT 的丰富性来自**真实材料、准确裁切、比例反差、字体层级、正式图表和有目的的收尾层**，不是来自随机色块、角标、圆形、厚箭头或每页相同的卡片网格。每页先让证据成立，再让画面有节奏。

## 色彩与材质角色

一套页面最多保留四类颜色角色：

| 角色 | 用途 | 使用纪律 |
| --- | --- | --- |
| 基底色 | 纸面、深色板或大面积留白 | 占约 60%—75%，稳定全套气质 |
| 中性色 | 正文、细线、图注、照片阴影 | 保证阅读，不抢结论 |
| 信号色 | 关键数值、状态、索引、单一箭头 | 占约 5%—10%，同一页只强调一种信息 |
| 材质色 | 来自实物、地图、PCB、日志或照片 | 只作深度/语境，不替代数据 |

可从项目图片中抽取一组深板、暖浅字和单一信号色；或使用深蓝绿、米白、哑金的编辑式组合。先依据主照片校色，再写入全套 token，不能逐页任意换色。暗底页面必须提升正文和细线对比度，避免教室投影后消失。

### 可选的“技术档案”起始 token

下列 token 可作为技术答辩/项目汇报的安全起点，而不是每页照抄的色卡。先以真实主照片校色；若场地投影偏暗，优先提高文字对比，不增加霓虹色。

| 角色 | 推荐值 | 用途与限制 |
| --- | --- | --- |
| 深色背景 | `#0B1210` | 深色数据页、章节页，避免纯黑死板感 |
| 深色面板/分隔 | `#121D19` | 网格、细分隔和局部层级 |
| 深底主文字 | `#F1EEE4` | 标题、正文和关键数字 |
| 深底次文字 | `#BEB9AA` | 条件、单位、图注和来源 |
| 主强调金 | `#C9A85A` | 一页中的单一关键结果、索引或状态 |
| 技术状态青 | `#65B9BE` | 串口、视觉或正常状态的少量标识；不与金色争夺主结论 |
| 风险提示橙红 | `#D06D5A` | 限制、异常或待验证项；同时配合文字/形状 |
| 浅色背景 | `#F4F0E6` | 结构说明、档案式结论页 |
| 浅底主文字 | `#1E2521` | 浅色页正文 |
| 浅底深褐金 | `#72551F` | 浅底上的金色文字；浅底 `#C9A85A` 只作装饰块 |

建议比例为：基底约 70%—85%，文字与中性线约 10%—20%，强调色通常不超过 5%；同一页只设置一个主强调色。

## 网格、留白与文字层级

- 默认使用 16:9、12 列或等效模块网格；外边距约为页面宽度的 5%—6%，列间距和页脚基线全套固定。先放 Hero，再确定文字区和辅助材料，不从居中标题开始。
- 一页只保留一个最高层级标题/结论；眉题、页码、坐标等只能承担导航。
- 中文优先使用交付稳定的无衬线字体（如微软雅黑或思源黑体）；标题用 SemiBold、正文用 Regular、等宽字体仅用于英文索引和数据。不要在一页混用多种装饰字体。
- 以投影可读性为下限：标题通常为 32—44 pt，结论/指标为 42—72 pt，正文为 20—24 pt，图注/坐标为 16—18 pt；内容塞不下时删减，不缩小字体。
- 线宽通常不低于约 1.0—1.25 pt；关键文字建议达到约 7:1 对比度，最低不得低于 4.5:1。照片上叠正文必须有稳定遮罩或底板。
- 留白要形成阅读停顿或区分责任区，不能是未被处理的空洞区域。

### 16:9 母版的绝对起点

在 13.333 × 7.5 in 的 16:9 页面中，先固定左右安全边距为 0.64 in、上边距为 0.45 in、下边距为 0.50 in；12 列之间的沟槽建议为 0.16 in。所有页面复用同一标题左基线、图注轨和页码位置，除非 Page Lock 明确允许全出血。

- 标题区从 y=0.50 in 开始，标题最多两行；结论句与主视觉的第一条对齐线必须全套一致。
- 底部 0.14—0.22 in 高的来源轨放置图号或 Asset ID、条件与页码；它服务证据回指，不承担正文。
- 页码固定在右下安全区，来源/条件固定在左下安全区；不要逐页移动导航元素来填空。
- 先建立三种可编辑母版：照片/档案页、技术拓扑页、验证数据页。封面和章节转场可以是这三种的克制变体，不能另起一套装饰体系。

## 六种页面视觉语法

| 模式 | 适用内容 | 推荐组成 | 避免 |
| --- | --- | --- | --- |
| 纪录片分栏 | 任务、现场、应用语境 | 宽景、明确文字区、实物证据插图 | 平均三栏照片 |
| 实物档案 | 硬件、创新点、装配 | 大图、两张不等大小细节、对比事实 | 整齐小缩略图墙 |
| 技术拓扑 | 架构、通信、控制 | 责任泳道/状态/数据流 + 一项真实记录 | 粗箭头加方框的假流程图 |
| 验证仪表 | 参数、日志、测试结果 | 深色或浅色数据板、少量强信号数值、测试条件 | 用大数字替代测试条件 |
| 视频证据舞台 | 验收、动作、过程 | 主视频帧、2—4 个证明节拍、简洁说明 | 只贴一个视频截图 |
| 编辑式结论 | 总结、展望、章节转场 | 大句子、克制情境材料、紧凑证据清单 | 空白大标题加无关装饰 |

相邻两页应至少改变一种主语法：主图方向、暗/亮底、文本位置、证据形态或阅读方向。系列页可共享导航和字体，但不能像复制粘贴。

## 图像处理与 Finish 层

Hero 通常承担 35%—60% 的视觉重量。Support 必须与 Hero 材料不同，例如“实物全景 + 焊接特写”“曲线 + 现场帧”“结构图 + 串口日志”。Finish 只能承担以下之一：定位、框定、节奏、深度。可用图注轨、坐标、测量刻度、项目材料半透明裁切、档案纸纹或低透明 PCB/机械轮廓；若不能说明作用，就删掉。

常规内容页必须同时有 Hero、Support、Finish。封面或章节转场可以省略 Support，但只能在 Page Lock 声明理由，并保留可读主句、可追溯主视觉或明确标注的情境材料，以及有功能的 Finish；这不是给空白页加随机装饰的许可。

照片先裁切，再统一明度、饱和度和边缘方式；避免同页所有图片相同大小、相同圆角、相同阴影。图内标注应与全套字体和颜色 token 一致，且保留原图、裁切说明和图注来源。

远距离审稿时，3 秒内应读到本页结论，10 秒内应找到主证据、单位/样本条件和证据边界。实物图、代码截图和日志可做明度/裁切处理，但不得篡改屏幕读数、识别框、实验物体、接线状态或测试曲线。

## 图表与流程图

- 流程、状态、责任和反馈先选择关系语法：路线、决策树、泳道、数据管线、闭环或约束图。
- 条件写在分支上，反馈使用第二线型或第二色，至少一处连接真实记录、照片或数据。
- 复杂拓扑使用 Draw.io、Graphviz、Matplotlib 或 SVG，保存源文件；不要手工堆出大量伪设备框。
- 曲线必须标出单位、样本、条件与数据来源；仿真和实测分开标注。
- 只有汇总统计而没有原始样本序列时，只允许做指标卡、统计表或条件说明条；不得虚构时序曲线、直方图、误差带或前后提升图。
- 同页出现不同设备、时段或条件下的数值截图时，不得用并列大小或共同坐标暗示可比性；裁切无关瞬时读数，或加入醒目的非可比条件标签。

## 反模式

- 每页都用四宫格卡片、相同角标、同一种深色大圆角；
- 先放文字，再用随机小几何“填满”；
- 外部氛围图被看成项目实物或测试证据；
- 为了“科技感”降低可读性、叠加发光、过度渐变或高饱和霓虹；
- 大标题、正文、图注、数据都争夺同一强调色；
- 一张小图、一段长文、大片未处理空白。
