# 资产先行的技术答辩 PPT 生产系统

本流程只负责把已有事实组织成有审美、有节奏、可答辩的页面；证据等级以本技能的 `evidence-boundary.md` 为准，可编辑图源以 `editable-visuals.md` 为准，渲染与交付以 `render-delivery.md` 为准。它不依赖报告、Word 或其他 Skill 的内部文件。

## Gate 0：范围与材料盘点

在排版前确认：答辩受众、总时长、页数、输入/数据版本（报告可选）、必须讲清的任务、不能超出的结论，以及 PPT 是否需要播放视频。先把用户提供的 PPT/素材副本放入 `ppt-workspace/input/`，记录名称、时间、大小和哈希或等效元数据；不直接覆盖用户源文件。扫描照片、视频、代码截图、日志、表格、结构图和已有图表；先填资产清单，再一次性汇总真正缺少的素材。

没有实测或用户确认支撑的内容，只能进入“设计解释”“应用设想”或“下一步验证”页面，不能为了画面完整而伪装为已验证成果。

## Gate 1：叙事与页面—证据映射

将整套内容组织成：

```text
问题/任务边界 → 设计选择或机制 → 已验证证据 → 限制与下一步
```

每一页只承担一个可在 15 秒内讲清的结论。为每页选定来源证据 ID、数据版本、可选报告图号、证据边界、讲解时长和可能追问；不要让一张页面同时承担“背景、结构、算法、数据、结论”五件事。

## Gate 2：页面锁定

在制作每页前，复制 `ppt-page-lock-template.md`。锁定四个对象：

1. **Hero**：主证据或主要视觉解释，通常占 35%—60% 的视觉重量；
2. **Support**：与 Hero 不同的材料或裁切，增加尺度、上下文、对比或可核查性；
3. **Finish**：图注轨、测量刻度、材料纹理、档案片段、坐标或色调板；必须能说明它如何定位、框定、调节节奏或制造深度；
4. **正式图/表**：可编辑源、数据范围、单位、图注和证据状态。

常规内容页缺少任一角色时，先选替代素材、合并页面、补拍/补导出，或明确占位；不使用无关形状凑画面。封面/章节转场已在 Page Lock 声明豁免时，可省略 Support，但不得省略可读主句、主视觉的证据等级和有功能的 Finish。

## Gate 3：三页校准

先完成并渲染三张最能决定全套气质的页：

- 封面/章节页：确定全局导航、色板和字体；
- 最难的技术机制页：确定拓扑、图表、注释和信息密度；
- 最强的验证/实物页：确定照片、数据和证据说明的关系。

若短 deck 只有 1—3 张内容页，第一张内容页可以同时承担章节/结构校准，不强制另做空洞封面；完整答辩仍应另设封面或结论页。短 deck 的每张内容页仍需遵守证据和版式规则。

只有这三页在相邻缩略图中形成统一又不重复的视觉节奏后，才批量制作其他页面。若用户已经给出明确参考风格，可直接据其方向校准；不要把每个中间线框都交给用户选择。

## Gate 4：逐页构建与内部返工

对每页重复：

```text
页面锁定 → 构建可编辑源 → 导出图片 → 全尺寸检查 → 相邻页检查 → 按量表返工
```

按内容选择视觉模式：纪录片分栏、实物档案、技术拓扑、验证仪表、视频证据舞台或编辑式结论。页面可共享字体、色板和导航，但相邻页至少在主图方向、暗/亮底、文本位置、证据形态或阅读方向上改变一项。

复杂结构、状态、责任边界、反馈和曲线使用 Draw.io、Graphviz、Matplotlib 或 SVG 等可编辑源；不手工堆砌伪设备框、粗箭头或不可复现的截图。

## Gate 5：渲染、演练与交付

1. 从最新获准的 `.pptx` 副本开始；保护用户命名的源文件。
2. 导出全部修改页和整套 contact sheet，既检查缩略图序列，也检查 100% 页面和投影可读性。
3. 对视频准备主片段、2—4 个关键帧和无法播放时的静态备份。
4. 在备注或答辩卡中写下每页讲解节拍、数据来源、局限和可能追问。
5. 保留可编辑 PPTX、图表源、资产清单、页面锁定卡、审稿记录、结构检查结果和最近三个可丢弃预览版本；交付目录中的版本号必须能回指输入副本。

## 缺少素材时的处理顺序

优先级依次为：现有项目证据的不同裁切/导出 → 补拍或补录 → 合并或下沉页面 → 搜索/生成并明确标注为情境或解释素材 → 向用户一次性请求缺料。不要在每做一页时反复索要随机照片，也不要让漂亮的外部素材压过项目证据。
