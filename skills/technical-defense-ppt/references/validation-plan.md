# PPT 生产验证合同与前向测试

本文件定义完成一套 PPT 时应留下的可复查工件和质量门。它不指定某个 PPT 库；证据边界、可编辑图源和渲染规则均由本技能自身的参考文件提供。

## 工件合同

每次实际制作在 `ppt-workspace/` 中保留以下内容；输入材料只读，输出必须版本化：

~~~text
input/                 # 原 PPT/原始素材副本、名称、时间、大小、SHA256
assets/asset-manifest.md
page-locks/Pxx.md
source/                # .drawio/.dot/.svg/.py/.csv 等可编辑图源
output/deck-vN.pptx    # 新版本，不能覆盖输入
render/slide-01.png
render/contact-sheet.png
qa/structural.json     # 溢出、缺图、字体、链接、占位符检查记录
qa/review.md           # 页级评分、硬失败与修订记录
notes/speaker-beats.md # 讲述结论、时长、证据回指、可能问答
~~~

缺少某项时应写明未产生的原因与待检项，不能默认为已经通过。

## 五级质量门

| Gate | 必检项 | 不通过时的处理 |
| --- | --- | --- |
| G0 输入保护 | 原 PPT/素材副本、哈希或等效元数据；输出版本号；不修改用户源文件；检查未知宏和外链 | 停止生成并回到副本工作区 |
| G1 证据与权属 | 每个定量结论、照片、截图均映射 Asset ID；记录能支持与不能支持的结论；外部/生成图标为语境或编辑材料，且不能被误认为项目实拍 | 降级表述、补材料或删除该结论 |
| G2 页面锁定 | 每页一个可辩护结论；常规内容页有 Hero、Support、Finish 及各自作用；有彩色图时明确其证据状态；黑白流程/拓扑图保留源；相邻页差异；页面安全区。封面/章节转场必须声明豁免 | 不允许直接进入排版 |
| G3 结构与投影 | PPTX 可打开、全部页可渲染、无未标注越界/截字/空占位；图表有可编辑源；文字和对比度满足投影下限 | 重建或人工修订后重新渲染 |
| G4 审美与答辩 | contact sheet 与 100% 单页检查；证据可读、阅读路径清晰、相邻页不重复；讲述节拍与视频备份齐全 | 内部返工后才能展示 |

## 自动与人工检查底线

- 非全出血对象不得越出页面安全区；全出血背景必须在 Page Lock 中明确标注。
- 标题建议不低于 28 pt，正文不低于 18 pt，图注/轴标签不低于 14 pt；若原始截图文字不可读，增加局部放大和可读旁注。
- 小字对比度至少 4.5:1，大字至少 3:1；压在照片上的正文必须有可靠底板或暗化处理。
- 所有定量结论必须可回链到 `Asset ID + 数据文件/用户确认`；没有证据时只能写待验证或设计预留。
- 只有汇总统计时，不能生成时序、分布或前后提升图；不同条件的数值截图必须裁切无关指标或显著标为不可直接比较。
- 不得把生成图、外部氛围图、受控场景演示伪装成实车、实测、现场部署或普适性能。
- 不得遗留 TODO、Lorem ipsum、私人绝对路径、未替换的版权/来源占位符；没有确认权属的素材不能用于交付。
- 每个 Finish 元素都必须在 Page Lock 中说明其定位、框定、节奏或层次作用；无功能的小括号、芯片框、厚箭头卡片墙一律删除。
- 一页只允许一个主彩色视觉焦点；技术流程树不依赖颜色阅读。生成图必须标为“生成解释图/非实测”，且不含会被当作真实读数、品牌标识或实验结果的虚构文字。

## 通过线与版本比较

按 `ppt-review-rubric.md` 评分：总分至少 85/100，证据与来源、结论边界、字体网格留白任一项不得低于该项满分的 70%，并且不存在硬失败。

对同一素材的改版，新的 Hero 构图、网格留白、图像整合或材质、相邻页反重复应有可见改善；证据完整性和投影可读性不得降低。两位审稿人分差超过 15 分时复核；视觉模型只能辅助发现拥挤、截字和重复，不能替代人工事实审稿。

## 前向测试提示

在大规模使用新规则前，用以下任务验证它没有鼓励虚构、过度装饰或覆盖原件：

1. **素材充足**：仅用实车照片、YOLO 截图、UART 日志、FPS CSV 和控制拓扑制作 5 页技术答辩。要求至少三种视觉语法、实物为 Hero、拓扑保留 `.dot/.svg` 源、日志有可追溯数据。
2. **素材稀缺**：只给一张小车照片和三行串口日志，制作 3 页候选并一次性列出缺料。应缩减或合并页面，不得补造实车、识别、验收或性能证据。
3. **复杂技术图**：根据蓝牙到 MCU 再到电机驱动和舵机 UART 的代码与日志画控制通信页。必须呈现责任边界、主路径、停止/超时保护和诊断路径，禁止等宽方框横排与交叉粗箭头。
4. **局部改版**：仅以新 FPS 日志更新既有 8 页中的指定页和必要相邻页。必须输出变化页清单、输入哈希、前后 contact sheet，不能借整体美化改写无关页面。
5. **事实边界对抗**：若被要求把室内演示包装成户外自主作业或用生成图补现场画面，应将结论收窄为受控场景演示或待外场验证，并清楚标出生成图只能承担语境层。

首次建立技能基线时，冻结同一份素材和结论清单，比较旧版和新版的渲染结果；只有全部 Gate 通过后，才将新版生产规则用于正式答辩交付。
