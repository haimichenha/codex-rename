# 模板优先与黑白技术图、少量彩色证据图片格式契约

本文件规定“用户给了模板或带格式要求文档”时的强制行为。模板不是内容灵感，也不是可随意改造成演示稿的素材；它是报告的版式、顺序和必填信息的上位约束。

## 1. 输入角色与优先级

先给每个输入文件标注唯一角色，避免把资料、模板和证据混在一起：

| 角色 | 常见输入 | 必须做什么 | 禁止做什么 |
| --- | --- | --- | --- |
| 模板 | 指定 `.docx`、往届示范、学校封面 | 保护副本、盘点样式/锚点、在原结构填充 | 新建一份不含原封面/摘要/页眉的“相似文档”替代它 |
| 格式要求 | 格式说明 Word/PDF、课程要求、学院规范 | 转成可执行的格式契约 | 用默认主题覆盖明确字体、字号、间距或页数要求 |
| 参考资料 | 已完成报告、任务书、论文、设计说明 | 提取事实、术语、图表和章节顺序 | 复制无证据的结论或把它当作空模板 |
| 证据 | 原始日志、数据、照片、代码、测量表 | 记录来源和可支持的结论 | 根据文件名猜测内容，或用设计图替代实测 |

优先级：**用户逐条指令 > 模板与格式要求 > 题目/课程规则 > 本文默认格式 > 审美偏好**。因此用户明确要求“无彩色字体/无彩色底纹/全篇黑白”时，必须覆盖模板既有蓝色、彩色表头和色块，但仍保留模板的页面结构、图片、页眉页脚与锚点。

## 2. 模板盘点清单

在创建任何正文前，必须完成下列盘点，并写入 `template-inventory.json` 与 `format-contract.md`：

1. **页面与节**：纸张大小、方向、页边距、分节、页码起始规则、页眉页脚；
2. **样式**：标题级别、正文、图题、表题、参考文献的字体、字号、字形、行距、段前后、缩进；
3. **固定页面**：封面、基础信息、诚信声明、任务书、摘要、关键词、目录、附录/参考文献入口；
4. **固定素材**：校徽、学院 logo、背景图、页眉线、已有插图、必填表格与签名栏；
5. **保留锚点**：将必须保留的标题/短语/表格标题写成可验证的文本锚点；
6. **可填充区**：确认从哪个标题/占位符开始替换内容，哪些段落只能追加不能删除；
7. **页数计划**：若用户要求 N 页，列出固定页占用和新增章节可用页数，不能为凑页数强制拆碎章节。

工具命令：

```powershell
python "<skill-dir>\scripts\init_template_report_workspace.py" "<template.docx>" `
  --workspace report-workspace
```

初始化脚本只读模板，并创建受保护输入副本、版本化输出副本、清单和格式契约骨架。`inspect_docx_template.py` 也可单独运行，用于复查已有模板。盘点结果不替代人工确认保护页范围。

## 3. 格式契约最小模板

`format-contract.md` 至少包含：

```markdown
# 格式契约

模板：<原始路径>
模板 SHA-256：<hash>
输出：report-workspace/output/<version>.docx
目标：<完整报告 / 指定章节 / N 页>

## 必须保留
- 页面/节：
- 文本锚点：
- 图片、图标、表格：
- 摘要/目录/附录规则：

## 样式映射
| 用途 | 使用的模板样式 | 字体/字号 | 行距/缩进 | 说明 |

## 新增内容限制
- 颜色模式：`template_inherit`、`new_content_monochrome` 或 `strict_monochrome_override`；用户明确禁止彩色时必须选 strict。strict 模式中，输出副本的**全部 Word 文本**改为黑色、表格/段落底纹改为白色、边线改为黑/灰；校徽、既有照片和位图图示不作为字体/底纹重着色对象。
- 表格：<模板样式或黑白三线表>。
- 图：<黑白 Graphviz/Mermaid/Draw.io；允许的少量彩色证据图及其预算>；图题样式：<模板样式>。

## 页数与章节预算
| 页/节 | 主结论 | 证据 | 图/表 | 预计篇幅 |

## 风格档案
- 采用档案与依据：
- 必须延续的模板/样稿特征：
- 禁止套用的通用版式：
- 与最近同类交付的必要差异：

## 尚待确认
-
```

如果用户明确指定字体、页边距、标题格式等，必须逐项落入此契约，不以“常用论文格式”取代。用户在生成后提出样式或内容修订时，其反馈优先级高于当前副本的审美选择。保留旧输出，从受保护输入或上一合格副本创建新版本；更新风格档案、逐项修正、渲染对照并在 `qa/revision-vN.md` 留下处理记录。不得以“已按默认格式生成”为由拒绝按新要求改稿。

后续材料补充还必须建立 `sections/material-delta-vN.md`。它列出旧/新来源、版本或时间、受影响页、关系（新增/替换/纠正/冲突待确认）与重验项目；新材料不得静默覆盖旧证据，也不能只追加到最后一页而不修正前文、摘要、表格和结论。

## 4. 黑白技术图与少量彩色证据图片规则

用户未要求颜色时，新增内容采用以下保守规则：

- 正文、标题、图题、表题、页码和注释都是黑色；背景为白色；
- 不新增彩色字体、彩色底纹、渐变、信息卡片、强调色条、彩色图例；
- 可使用黑、深灰、浅灰的线条区分层级，但线型、节点形状和标签必须同时承担区分作用；
- 表格使用模板既有样式。若无样式，使用白底黑线三线表：顶线/表头下线/底线略粗，内部线细或按学校规范；
- 允许保留模板已有的彩色 logo、插图和官方固定页面，不将其重新着色；
- 流程图默认白底、白色节点、黑色边框、黑色文字、黑色箭头。需要强调分支时使用虚线/双线/线宽/节点形状，不使用颜色。
- 用户明确允许或材料确有必要时，可在约八页的报告中新增 1—2 张彩色实物/现场/相机证据图，或使新增彩色图片总面积不超过新增图形面积约 20%；详见 `visual-color-policy.md`。图源、来源、证据状态与“能/不能证明”必须登记，彩色图不承担流程语义。

## 5. Word 副本编辑策略

1. 先用 Word/LibreOffice/OfficeCLI 打开**输出副本**，保留已有分节、样式、头尾、目录域和图片关系；
2. 仅在已确认的可填充区插入内容，优先套用相邻模板段落/图题/表题样式；`strict_monochrome_override` 下，在输出副本完成内容编辑后运行 `scripts/normalize_docx_monochrome.py` 生成下一版本，不能只保留原模板的蓝色标题再宣称黑白；
3. `python-docx` 适合写入结构化内容，但它可能破坏复杂字段、文本框、目录和浮动图。遇到这类模板时，不得“重建一份类似样式”，应改用 Word 自动化或人工副本操作；
4. 不删除封面、摘要、任务书或目录来凑页数。页数不足时补充有证据的实现细节、测试条件、表格或附录；页数超出时压缩重复表述和低价值截图；
5. 摘要位置和关键词样式必须保留。只有正文证据闭环后才在该位置回填摘要；否则明确保留待定占位，不编造结论。

## 6. 图表与论文式文字

### 6.1 朴素黑白流程图

可由代码生成的流程图应满足：

```dot
digraph flow {
  graph [rankdir=TB, bgcolor="white"];
  node [shape=box, style="rounded", color="black", fontcolor="black",
        fillcolor="white", fontname="SimSun"];
  edge [color="black", fontcolor="black", arrowsize=0.7];
}
```

若图表达分支或状态树，应展示条件、失败出口、超时/复位/安全处理，而不是只画“开始—处理—结束”三块。图内字不小于模板图题可读性的下限；细节放在图注和正文。

### 6.2 表格

- 每个表只回答一个问题：接口映射、参数来源、测试步骤、结果、故障定位或证据状态；
- 标题位于表上方、图题位于图下方，编号连续并在正文首次出现处引用；
- 没有实测数据时，表头应写“计划/待验证/设计参数”，不能伪装成“测试结果”；
- 禁止为了填页堆叠“模块—功能—优点”一类重复表。

### 6.3 论文式正文

正文不是 PPT 讲稿。优先使用：研究对象/任务、具体方法、输入输出、测试条件、观测结果、限制和下一步。避免“随着……发展”“具有重要意义”“显著提高”“完美实现”等无来源套话。没有模板时的标准默认值见 `SKILL.md`；模板有规定时一律听模板。

## 7. 交付前的格式门

交付前必须同时通过：

1. 源模板哈希未变，输出文件不是源模板；
2. 保护锚点、封面/基础页、摘要位置和必填图标/插图仍存在；
3. 目标页数、纸张/方向、标题层级、页眉页脚、编号和目录规则满足契约；
4. 新增内容没有超出模板基线的彩色文本或彩色底纹；新增彩色图片已在预算内并登记来源、证据状态和限制；
4a. `strict_monochrome_override` 时，运行 `validate_docx_template.py --strict-monochrome`，并确认文字颜色和底纹违规列表为空；
5. 每个新增图表有源文件、图注、编号和证据状态；
6. 所有“已完成/达标”有原始证据可回链；
7. `.docx` 与渲染 PDF/PNG 均已检查。发现格式偏差时，先修副本后交付，不以截图替代可编辑 Word 文件。
