# 报告到答辩 PPT 的衔接

PPT 不是把报告段落逐页缩短，而是把报告中已经成立的结论组织成一条可讲、可看、可被追问的证据链。先从报告的图号、参数表、实物照片、日志和限制条件中提取素材，再进入排版。

## 进入 PPT 阶段的前提

- 每个核心结论已有报告中的证据来源和边界；
- 报告与 PPT 使用同一数据版本、术语和图号；
- 未验证的内容保留为“下一步验证”或“应用设想”；
- 已明确答辩受众、总时长、预计页数和需要回答的关键问题。

答辩时间很短时，优先删减背景知识，不删掉结论边界、测试条件和能回指的证据。

## 五步衔接

1. **叙事映射**：把报告章节压缩为“问题/目标 → 设计选择 → 机制 → 验证 → 局限与下一步”，每页只承担一个可讲结论。
2. **资产包**：按 `ppt-asset-manifest-template.md` 标记证据状态、用途、裁切潜力和版权；先找全素材，再开始做页。
3. **页面锁定**：按 `ppt-page-lock-template.md` 决定结论、Hero、Support、Finish、图表源、视觉模式与相邻页差异。
4. **逐页生产**：按 `ppt-production-system.md` 和 `ppt-design-language.md` 制作、导出、目视检查和内部返工；不要把未完成的线框图交给用户“靠装饰补救”。
5. **全套演练**：按 `ppt-review-rubric.md` 检查结论边界、证据清晰度、投影可读性、相邻页节奏、视频播放和 Q&A 提示；按 `ppt-validation-plan.md` 留下输入保护、渲染、审稿和版本回指工件。

## 建议的机器人答辩骨架

1. 任务与验收边界；
2. 总体结构、供电和接口；
3. 本人负责的机械、焊接、代码或调参工作；
4. 关键机械/控制设计选择；
5. 视觉、通信或算法机制；
6. 实测验证记录与实物演示；
7. 局限、可扩展方向和结论。

页面顺序可因任务调整，但不能让“应用前景”替代已验证结果，也不能用单张演示照片代替成功率、精度或鲁棒性数据。
