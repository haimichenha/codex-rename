# 输入驱动的风格档案与反馈改稿

## 1. 风格不是默认皮肤

每次新任务先以以下优先级建立 `sections/style-brief.md`：用户逐条要求 → 指定模板/样稿 → 课程或竞赛格式 → 文档用途与受众 → 无约束时的论文默认值。不要从上一份报告复制章节标题、图表排列、配色或句式；同一项目的“实验记录”“设计报告”“验收台账”也应因用途不同而采用不同组织方式。

`style-brief.md` 最小内容：

```text
输入与用途：
受众与页数：
采用的风格档案：模板延续 / 课程论文 / 实验记录 / 竞赛设计报告 / 用户样稿延续
必须保留的字体、编号、标题、留白、页眉页脚、图表和色彩特征：
可用图像策略：黑白技术图 / 原始彩色证据图数量 / 明确标注的解释图：
明确禁用：例如彩色卡片、演示稿式大标题、统一三栏、过密表格：
与最近同类交付的必要差异：
```

## 2. 常用档案的选择规则

| 档案 | 适用输入 | 版式与文风 | 图表策略 |
| --- | --- | --- | --- |
| 模板延续 | 用户指定 DOCX/往届报告/院校样稿 | 复用原有封面、样式、页眉与章节节奏；不“美化重建” | 延续模板图题和表格，新增图先满足模板可读性 |
| 课程论文 | 有明确论文规范、无可编辑模板 | 正式标题层级、论证段落、章节/引用完整 | 黑白技术图、三线表；色彩仅按要求或证据策略 |
| 实验记录 | 日志、测量、步骤、故障定位为主 | 条件—操作—观察—证据—限制的时间/因果顺序 | 原始日志摘录、标注照片、数据表；避免大段背景介绍 |
| 竞赛设计报告 | 赛题、系统方案、评分项、模块证据 | 任务/约束—系统分工—关键机制—验证边界 | 任务图、责任图、计分/证据矩阵；不把设计示意写成得分结果 |
| 用户样稿延续 | 用户给了明确视觉或排版参考 | 优先模仿其可观察的层级、密度与材料组织，而非泛化审美 | 保持样稿的图文比例和图题规则，同时保留可编辑源 |

档案可组合，但每个组合必须明确哪个输入决定字体、哪个决定章节、哪个决定图片策略；冲突时回到优先级，而不是折中成通用卡片文档。

## 3. 防同质化检查

交付前回答：

1. 若遮住文件名，能否从模板/要求/素材中看出这份报告属于本次任务，而不是上一份的换词版本？
2. 本次的章节顺序、表格、图片和结论是否由实际证据与格式要求决定？
3. 是否错误套用了上一次的八页分配、流程图、色彩或文风？如有，删除或按本次 style brief 重做。
4. 若模板要求彩色/图文型版面，是否错误地把它洗成纯黑白论文；若模板要求正式论文，是否错误地套成演示稿？

## 4. 用户反馈后的强制修订循环

用户说“不符合预期”“不按要求”“太千篇一律”“按这个样稿改”等，立即执行：

1. 将反馈逐条写入 `qa/revision-vN.md`，标注涉及内容、格式、视觉、事实边界或页数；不把反馈解释为可选建议。
2. 对照用户要求、模板和当前 `style-brief.md` 写差异清单；发现旧档案选择错误时更新 style brief。
3. 从上一合格副本建立 `output/<name>_vN+1.docx`，不覆盖模板、输入副本或上一个交付版本。
4. 只复用本次仍满足要求的素材；重建不合格的段落、图表和版式。不得只替换标题或色彩来伪装“已修改”。
5. 重新导出 PDF/页面渲染，复查反馈点、模板锚点、页数、字体、图表源与事实边界；在 `qa/revision-vN.md` 记录每项反馈的处理结果。

用户没有限定修订范围时，先从其明确否定的维度开始整体修正；不要要求用户重复已提供的模板、样稿或格式要求。

## 5. 旧材料补充新材料：增量合并与修复

旧文档不是一次性成品。用户补充日志、照片、测量数据、代码版本、模板页面、评分规则或更正说明时，先创建 `sections/material-delta-vN.md`，而不是直接追加内容：

| 旧来源/结论 | 新来源/版本/时间 | 关系 | 受影响内容 | 处理动作 | 复检项 |
| --- | --- | --- | --- | --- | --- |
|  |  | 新增 / 替换 / 纠正 / 冲突待确认 | 章节、表、图、摘要、结论 | 补充 / 重写 / 删除 / 标待确认 | 渲染、交叉引用、证据边界 |

执行顺序：

1. **保护与盘点**：旧模板、旧输出、旧证据和新材料都保留路径、哈希/时间与角色；新材料不能覆盖原始日志或照片。
2. **语义比对**：以对象、任务号、参数名、单位、时间、测试条件和证据等级匹配材料。仅同名文件不构成“替换”；条件不同则并列标注，不伪装为同一试验。
3. **决定关系**：新材料扩展范围时标“新增”；给出同条件且更高可信度数据时标“替换”；指出错误时标“纠正”；互相矛盾且无法判断时标“冲突待确认”。
4. **最小但完整修复**：从上一版本副本生成 `vN+1`，更新所有受影响的正文、图/表、图题、交叉引用、摘要、结论和限制；保留未受影响的模板与合格内容。不要只在文末粘贴补充说明。
5. **重验与回链**：重新渲染、检查页数/版式/编号，确认每个更新后结论能回链到正确材料。若新材料降低了结论可信度，必须收窄或撤回旧结论。

新材料只证明一个局部条件时，只更新该条件下的表述；不得反向宣称旧的全流程结果已经被新局部材料验证。发生冲突时，在报告中保留“待确认”边界，并一次性向用户列出所需的判定材料。
