# 实验报告写作风格与摘要后置

## 摘要规则

摘要不是正文提纲，也不是在材料尚未齐全时预先编造的“结论”。在全部正文、图表和结论定稿之前：

- 保留模板中的摘要标题和位置；
- 草稿中只写 `【正文、图表和结论定稿后编写摘要】`；
- 不提前填写关键词、性能数字、成功率或“达到预期”等结论。

定稿时按“任务对象 → 实现方法 → 已核验的结果 → 限制/结论”压缩成一段，所有数字和结果必须能在正文中找到来源。

## 自然、具体的实验文风

目标是让文字像实验记录和工程说明，而不是泛化的自动生成段落。

### 应当使用

- 明确主语：`本次搭建的四轮小车`、`STM32F103ZET6 控制板`、`蓝牙控制页面`、`舵机驱动板`；
- 明确动作：`接入`、`烧录`、`发送`、`记录`、`观察`、`调整`、`复位`；
- 明确条件：电源状态、连接方式、PWM、串口、动作序列、测试场地和照片/日志来源；
- 明确边界：`本次仅记录偏航角，不将 LADRC 输出写入电机 PWM`、`该照片用于展示装配状态，不作为速度性能数据`；
- 短句和长句交替，一段只说明一个工程事实或一个判断。

### 避免使用

- 空泛起手式：`随着……的发展`、`在当今时代`、`具有重要意义`；
- 堆叠连接词：`首先、其次、然后、最后` 连续罗列；
- 无来源评价：`显著提高`、`极大提升`、`先进可靠`、`完美实现`；
- 重复总结：每段末尾反复写 `综上所述`、`可见`、`值得注意的是`；
- 把设计意图写成测试结果，或把一次演示写成稳定性能指标。

## 论文式组织，而非统一模板腔

报告的段落要由证据和模板位置决定，不由固定的“万能六段式”决定。用户给出的示范模板存在方案比较、理论计算、实现、测试、结论等章节时，沿用该章节序列、编号和样式；不要把它改造成每页都含“背景—目标—方案—优势”的重复卡片。

- **方案章节**：说明候选方案、取舍依据和最终接口边界；
- **实现章节**：说明模块、输入输出、关键参数及其来源；
- **测试章节**：先写条件和步骤，再写原始数据/日志范围、现象和可得到的结论；
- **问题与结论章节**：将设计完成、软件验证、实测结果和待补项分开；
- **摘要**：只在正文全部定稿后回填到模板已有摘要位置，不能删除摘要页或另造一页摘要。

没有格式要求时可采用常见中文论文默认：正文宋体小四、黑色、1.5 倍行距、首行缩进两字；标题黑体并按层级递减；图题/表题黑色且连续编号。只要模板或学院规范给出不同格式，就以它们为准。

### 改写示例

不写：`系统通过先进算法显著提高了小车运行稳定性。`

写成：`固件保留了陀螺仪角度读取和 LADRC 观测日志。本次蓝牙测试仍采用固定 PWM 与定时脉冲控制，尚未把观测输出闭环叠加到四轮 PWM。`

不写：`机械臂能够高效完成抓取任务。`

写成：`在“抓取”动作组下，六路舵机按预设位置发送到驱动板；验收照片记录了机械臂夹持物品的状态。`
