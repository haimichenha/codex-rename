# 报告证据与章节规则

## 证据状态

| 状态 | 可用于 | 不可用于 |
| --- | --- | --- |
| 实测证据 | 实验结果、图注、参数表、结论 | 超出测量范围的性能承诺 |
| 用户确认 | 设备配置、操作事实、已观察现象 | 未提供条件下的精确数值 |
| 推导/待验证 | 设计思路、下一步计划、风险说明 | 写成“已验证”“达到” |

每项证据记录：文件路径、来源、采集日期（若已知）、关联章节、可支持的结论、限制条件。串口日志和照片不要只靠文件名猜测含义；不明信息先向用户确认。

## 章节写作模板

1. **任务与指标**：题目给出的目标与约束，不虚构验收指标。
2. **总体方案**：车体、驱动、电源、通信、机械臂与感知模块的边界和数据流。
3. **硬件与接口实现**：引脚、串口和供电关系；以原理图、代码或接线照片为依据。
4. **软件与控制实现**：蓝牙命令、运动状态、舵机协议、诊断/控制算法；明确“已闭环”还是“仅记录/观测”。
5. **实验设计与结果**：测试步骤、条件、原始数据、现象、结果表/图和可复现实验方法。
6. **问题、改进与总结**：把未完成闭环、样本不足、环境因素等限制写清楚。

实际模板的标题、编号、封面和页眉页脚优先于以上建议；先以模板为准建立映射。

## 章节完成判定

一个章节只有同时满足下列条件才标为“可交付”：

- 标题和内容与模板层级一致；
- 每个关键数值有来源；
- 图、表、正文编号互相引用；
- 结论没有超过证据边界；
- 已完成一次渲染或人工版式检查；
- 未补材料列在章节末尾，而非静默遗漏。
