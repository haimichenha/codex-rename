# 模板优先实验报告套件

## 职责与连续性（优先执行）

- **这是唯一的 Word 报告生产入口**：用于实验报告、技术报告、竞赛设计报告的 `.docx/.pdf` 创建、重建和修订；绝不创建、修改或排版 `.pptx`。PPT 一律交给 `technical-defense-ppt`。
- **模板约束跨后续消息持续有效**：同一会话或工作区中，一旦用户给过模板、原报告，或说过“保留封面/基础信息页”，后续的“再生成”“重做”“换资料”“试一下效果”仍是模板绑定任务。仅给出新的图片/资料目录只改变内容来源，**不**解除保留范围。
- 开始前必须将保留范围写成且只写成一项：`保留全部模板结构`、`仅保留基础信息页`、或`用户列明的自定义范围`。范围不明确时，默认保留全部模板结构；不得退回通用论文模式。
- 用户说“不限页数”时，采用连续流式排版；除模板规定的封面、分节或用户明确要求外，不得按章节强制分页制造大面积空白。
- 用户明确要求“除基础信息页外全部更新”时，只保护该基础信息页；摘要、正文、图表、附录和旧锚点均可按增量台账替换，并为该例外建立最小保护锚点清单。

本技能交付的是**可编辑、格式合规、证据可追溯**的 Word 实验报告。它不是“把材料改写成一篇通用彩色报告”的工具：用户给出的模板、封面、基础信息、图标、摘要页、任务书、目录、页眉页脚和格式要求，默认比生成内容优先。

## 不可突破的交付原则

1. **格式优先级固定**：用户明确要求 > 指定模板/示范文档 > 单独格式要求文档 > 院校/课程规范 > 本技能的黑白论文默认值。低优先级不得覆盖高优先级。
2. **模板只读、成品基于副本**：绝不改写用户原始 `.doc`/`.docx`。先将其复制到 `report-workspace/input/`，记录哈希；在 `report-workspace/output/` 创建副本并在副本上编辑。
3. **模板绑定模式是默认**：用户说“按这个模板”“保留封面/基础信息页”“使用此 DOCX”时，必须先执行模板盘点。未经用户明确允许，不得删除或重建以下内容：封面、基础信息页、校徽/图标、已有插图、摘要和关键词、目录、任务书、必填表、页眉页脚、参考文献/附录入口。
4. **不以通用文档替代模板**：有指定模板时，不能新建一份视觉相似但结构不同的报告，也不能用统一“卡片式/演示稿式”版面覆盖模板。若工具无法保留复杂模板格式，停止在副本保护与盘点，改用 Word/LibreOffice/OfficeCLI，或请用户提供可编辑模板副本。
5. **颜色模式必须显式判定**：默认仅让新增正文、表格、流程图和图注使用黑色文字、白色背景、黑/灰线条；模板原有彩色徽标、图片和样式可保留。若用户明确写出“无彩色字体”“无彩色底纹”“全篇黑白”或等效要求，切换到 **strict monochrome override**：该用户要求高于模板色板，必须保留封面、基础信息、图片、结构和页眉页脚，但将输出副本中的 Word 文本改为黑色、表格/底纹改为白底黑线；不得以“模板原来是蓝色”为由保留彩色标题、文字或表格填充。用户允许或材料确有必要时，新增彩色图片仅限少量可追溯的实物/现场/相机证据或明确标注的解释示意，并遵循 `references/visual-color-policy.md`。
6. **先证据、后结论**：将每项内容标为 `实测证据`、`用户确认` 或 `推导/待验证`。没有日志、照片、数据或用户确认时，不能写成“已完成、达标、稳定、成功率”。
7. **图表服务论证，不作装饰**：流程图、树图、结构图和表格必须回答正文中的一个问题；保留 `.drawio`/`.dot`/`.mmd`/`.py` 等源文件。没有实测数据时只能画“设计示意”，不能伪造成实测曲线。
8. **风格由输入决定，不套固定成品**：模板、课程/竞赛要求、用户提供的参考文档、受众和文档用途共同决定版式、文风、图表密度与允许色彩。不得把所有任务做成同一种“黑白八页论文”或同一种卡片化版面；只有无格式约束时才使用论文默认值。详见 `references/style-profiles-and-revision.md`。
9. **反馈触发重做，不为旧结果辩护**：用户指出“风格不对、没有按要求、结果不符合预期”时，该反馈立即覆盖旧的审美假设。保留旧版本，提取差异、在新版本副本中修正、重新渲染和质检；不得以已经生成过文件为理由拒绝修改。
10. **新旧材料增量合并、可纠错**：后续补充的日志、照片、参数、模板页或格式要求必须先与旧材料做来源、时间、条件和结论影响比对，再按“新增 / 替换 / 纠正 / 冲突待确认”处理。不得只把新资料附在末尾，也不得因新材料而丢失仍有效的模板锚点、原始证据与既有可复核内容。详见 `references/style-profiles-and-revision.md`。

详细模板规则见 `references/template-first.md`；证据与章节规则见 `references/core.md`。

## 触发后的必经流程

### 0. 判定工作模式

| 用户输入 | 工作模式 | 必须动作 |
| --- | --- | --- |
| 指定 `.docx`、示范报告、模板或“按照格式” | 模板绑定 | 先盘点样式、保护页和保留锚点；从副本编辑。 |
| 单独给出格式说明/PDF | 格式契约 | 将字体、字号、间距、页边距、标题级别、图表和引用要求写入 `format-contract.md`。 |
| 只给材料、不提供格式，且不是已知模板任务的后续消息 | 论文默认 | 使用本技能黑白论文默认值，并在交付中声明。 |
| 只要求某章/某图 | 小步交付 | 只完成该部分，不重排其他章节。 |
| 明确要求“完整 N 页报告” | 整体交付 | 先冻结模板和页数分配，再生成、渲染并质检全稿。 |

“小步交付”不再阻止用户明确要求的完整报告；完整报告仍必须经过全稿渲染检查。

### 1. 模板盘点与格式契约（先于写作）

1. 运行只读预检：

   ```powershell
   & "<skill-dir>\scripts\preflight_report_tools.ps1" -TemplatePath "<模板路径>"
   python "<skill-dir>\scripts\init_template_report_workspace.py" "<模板路径>" `
     --workspace report-workspace
   ```

   初始化脚本会创建输入保护副本、版本化输出副本、`template-inventory.json` 和格式契约骨架；它拒绝覆盖已有输出。需要复查模板时可单独运行 `inspect_docx_template.py`。

2. 完成 `report-workspace/format-contract.md`，至少记录：
   - 原模板哈希、页边距、纸张方向、页眉页脚、标题/正文样式；
   - **保护页与锚点**：保留哪些页面/标题/图片/表格，允许从何处开始填充；
   - 字体、字号、段前后、行距、首行缩进、编号、图题/表题、参考文献格式；
   - 目标页数与每页/每章信息预算；
   - 明确颜色模式：`template_inherit`、`new_content_monochrome` 或 `strict_monochrome_override`；用户明确禁止彩色时必须选第三项。
3. 在写作前建立 `sections/style-brief.md`：记录本次输入对应的风格档案、必须复用的模板特征、明确禁用的通用版式、图表/色彩策略和与最近同类交付的差异点。若用户已给出视觉/格式样稿，样稿是上位约束，不得退回默认论文样式。
4. 若模板是 `.doc`，先用 `convert_legacy_doc_copy.ps1` 生成输出副本；不要让 `python-docx` 直接处理 `.doc`。
5. 先给出“模板保留清单 + 章节映射 + 图表清单”。若用户未要求直接生成，等待确认；若用户已经明确要求完整报告，可继续，但不能猜测模板中不清楚的必填字段。

### 2. 建立材料、章节和页数计划

在项目中建立（或续用）以下工作区：

```text
report-workspace/
  input/template/           # 原模板、原报告和格式要求的只读副本
  input/fuel/               # 原始图片、日志、数据表、代码说明和文字资料
  evidence/                 # 日志、照片、测量表、代码路径说明
  figures/source/           # .drawio/.dot/.mmd/.py/.csv
  figures/export/           # 插入 Word 的 SVG/PNG/PDF
  sections/                 # 章节卡片、引用与待补证据
  output/                   # 仅此处放版本化 .docx/.pdf
  template-inventory.json
  format-contract.md
  manifest.json
  qa/
  showcase/                 # 可选：从最终 PDF 派生的页面预览与联系表
```

`input/fuel/` 是未加工材料仓；在 `evidence/` 建立可回链的证据台账后，材料才能支持正文结论。先依据模板、材料台账和章节卡片输出版本化初版 `v0`，再从渲染审稿和用户反馈依次生成 `v1`、`v2`……；不得覆盖模板、燃料或已确认版本。

每个章节先写卡片：

```text
章节与目标：
模板中的对应位置/样式：
允许使用的证据（文件 + 来源 + 时间）：
关键参数及来源：
需要的图/表与其结论：
必须保留的模板锚点：
待用户确认/待实测：
```

整体交付还要给出每页的“主结论 + 一张关键图/表 + 预估字数”，防止每页重复“系统由……组成”的泛化段落。

用户在旧报告基础上补充材料时，先新增 `sections/material-delta-vN.md`：登记旧来源、新来源、时间/版本、受影响章节、处理动作（新增/替换/纠正/待确认）及需要重验的摘要、表格、图题和结论。没有这份增量台账，不得直接把新资料拼接进旧稿。

### 3. 撰写与版式

- 先使用模板已有的 Word 样式；不得用直接格式把模板统一洗成新字体/新布局。
- `strict_monochrome_override` 是唯一例外：保留模板结构和非文字图片，但按用户要求把输出副本的文本和表格样式中和为黑字、白底、黑/灰线。先用 `scripts/normalize_docx_monochrome.py` 创建下一版本，再用 `validate_docx_template.py --strict-monochrome` 审计；不要手工只改新增段落后宣称“全篇黑白”。
- 不同输入要产出不同、但可追溯的风格：例如严格课程模板延续其标题/编号/留白，实验记录强调条件—操作—观察—限制，竞赛设计报告强调任务—系统—验证证据。禁止不看材料就复用上一份报告的章节句式、图表排列或结论措辞。
- 新增文字按“任务/问题 → 方案/方法 → 实现 → 测试条件与证据 → 结果或限制”写。一段只说明一个可核查工程事实。
- 使用 `references/writing-style.md` 的论文式写作规则；拒绝泛化导言、无来源形容词、重复总结和把设计意图写成结果。
- 新增表格优先使用模板表格样式；没有时用简洁黑白三线表或单线表。表头黑体/加粗、白底，表内文字黑色；不使用彩色表头或色块。
- 只有正文、图表、结论和限制均已回链时才填写摘要和关键词；如果模板已有摘要页，**保留该页的位置、标题和样式**，只在该位置回填合规摘要。

### 4. 生成图、表与图注

1. 每幅图先填写图形卡片（目的、来源、状态、源文件、导出物、限制）。
2. 流程、状态、通信、软件层级优先用 `.drawio`；不可用时用 Mermaid 或 Graphviz。默认使用朴素黑白流程图/树图：白色节点、黑色轮廓、黑色箭头、灰度线型，足够详细但不堆装饰。彩色图片只补充实物、现场或视觉画面，不能替代技术图。
3. 曲线只允许由真实 CSV/日志或可验证的仿真模型生成，并写清单位、条件、数据范围及“实测/仿真”。
4. 图片只做裁剪、比例统一和必要的黑白标注；原图留在 `evidence/`。图题、图号与正文交叉引用必须一致。

### 5. 渲染、审稿与格式门

1. 导出版本化 `.docx` 和 `.pdf`，渲染每页 PNG/contact sheet。
2. 目视检查封面/基础页、目录/摘要、每个新增章节页和最后一页：页数、空白、标题层级、页眉页脚、表格跨页、图像清晰度、中文字体、编号、孤行/寡行、图表与正文的对应关系。
3. 运行格式审计：

   ```powershell
   python "<skill-dir>\scripts\validate_docx_template.py" `
     --template "<模板路径>" --output "<报告副本.docx>" `
     --inventory report-workspace\template-inventory.json `
     --out report-workspace\qa\template-style.json
   ```

4. 下列任一项失败时必须修正后再交付：保护锚点丢失、模板关键页面被重建、页数不符、字体/格式契约不符、新增彩色字体/彩色底纹、未登记或超预算的彩色图片、图表无源文件、图题编号不一致、把待验证事项写成结论；`strict_monochrome_override` 下，任何非黑色 Word 文字或非白色文字/表格底纹均为失败。
5. 用户有明确修订反馈时，完成“反馈 → 差异清单 → 版本化副本 → 渲染对照 → 复检”循环。确认过的原件和上一个版本都只读保留；修订版本不能覆盖它们。
6. 增量补料后，复核所有被影响的摘要、参数表、图题、交叉引用、结论、限制和页数；新材料若推翻旧结论，必须同步修正文中每个受影响位置，不能只在附录留下矛盾版本。

### 6. 效果展示预览（仅在用户要求时）

- 用户说“看看效果”“图片效果”“展示报告”或需要向他人快速预览版式时，从**已通过质检的最终 PDF**派生 `showcase/vN/`；不得为了展示而重排、截图替换或改写 `.docx` 正稿。
- 使用 `scripts/render_report_showcase.py --input <final.pdf> --output report-workspace/showcase/vN` 生成预览；脚本拒绝非 PDF 输入和非空输出目录，默认 144 DPI。
- 预览至少生成逐页 PNG 和一张联系表；若只需要展示重点，可额外导出封面/基础信息页、系统方案页、关键证据页和结论页，并明确它们只是版式预览，不构成新的实验结论。
- 展示预览与 `qa/` 相互独立：`qa/` 服务审稿，`showcase/` 服务浏览或演示；两者都不是报告正文，也不得覆盖 `output/` 的版本化 `.docx/.pdf`。
- 如需把报告作为 PPT 的资料，只能将最终 PDF 或展示 PNG 作为 `technical-defense-ppt` 的只读 `input/fuel/`；不得由本技能创建或修改 PPT。

详细目录、命名和公开展示边界见 `references/showcase-preview.md`。

## 论文默认值（仅无模板/无格式要求时）

- A4、上下 2.54 cm、左右 3.17 cm；中文正文宋体小四（12 pt），英文与数字 Times New Roman；黑色文字、白色背景；1.5 倍行距、首行缩进 2 个汉字。
- 一级标题黑体 16 pt，二级标题黑体 14 pt，三级标题黑体 12 pt；图题/表题宋体 10.5 pt，均为黑色。实际学校模板优先。
- 图表按出现顺序编号；正文用“如图 2-1 所示”“见表 3-2”交叉引用；表格默认白底黑线，不使用彩色填充。

## 交付说明

交付时只报告：输出文件路径、模板保留清单、格式契约与本次风格档案摘要、图源/证据清单、渲染与格式审计结果、仍待补的实测材料；若已生成效果展示，另列出 `showcase/` 路径及其对应的最终 PDF 版本。不得将“设计示意”或“格式通过”表述成系统性能已验收。
