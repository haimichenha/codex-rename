# 简历版式与照片规则

## 先建立层级，而非堆装饰

- 信息层级：姓名/目标岗位 > 教育与核心项目 > 项目职责与成果 > 技能和链接。
- 每个分区最多一条细灰分隔或留白；不要同时使用粗蓝线、蓝色底、图标和边框。
- 保持可打印：深色标题区可选，正文应以黑/深灰文字和白底为主。
- 保留足够边距；避免依靠极小字号和负行距“塞满一页”。

## 元素调整顺序

0. 先确认是否已有用户认可的 PDF/DOCX 母版；若有，保留它的总体风格、页眉比例、照片策略和正文密度，不要重新设计。
1. 先定页面尺寸、页边距、栏宽和表格固定布局。
2. 再定标题、正文、辅助文字、链接四级字号与行距。
3. 再处理分隔线、浅灰底、项目标签等低优先级元素。
4. 最后放照片，导出 PDF 再微调。照片不应迫使正文过度压缩。

## 照片的两种方案

### 视觉优先：浮动照片 + 表格网格

用一行两列的无边框表格控制左侧深灰标题块与右侧留白，照片设为“浮于文字上方”。它不必塞入单元格，因此可以比深色块略高，或在白底照片区保留更舒服的比例。

- 以表格列线和标题块边缘作为手动对齐基准；
- 若用户要求照片“显得大”，允许照片高度略高于左侧填充块，但左右位置仍应稳定在白底照片区；
- 在“更多布局选项”中将照片位置固定为相对页面/页边距，锁定锚点；
- 固定照片尺寸和横纵坐标后，必须同时检查 Word、PDF 与打印预览；
- 不将照片覆盖在正文、联系方式或页面边界上。

这是照片比例需要独立控制时的推荐方案。用户已经否定嵌入式照片时，此方案是默认方案；不要因为脚本更容易实现而回到嵌入型。

### 稳定优先：嵌入型照片

外层表格一行两列。左格深灰、右格白底；图片嵌入右格，段落水平居中，单元格垂直居中。适合照片与标题块齐平、后续还会频繁改动文字的情况。其局限是照片尺寸会受单元格和行高约束。

只有在用户明确接受照片与标题块齐平、或优先要求 Word 内稳定自动对齐时，才使用嵌入型照片。

## 内容密度与不丢要点

- 用户给出完整正文时，先做承载排版，不要擅自改成短版。
- 一页放不下时，先压缩行距、栏宽、链接索引字号和重复措辞，再删低优先级内容。
- 不删：获奖项目职责、个人承担模块、日期、奖项等级、项目 P 编号、完整 GitHub 链接、可验证指标。
- 可压缩：重复的“个人职责”、过长连接词、重复出现的团队项目说明、部署链接说明文字。
- 对外投递版本中，管理后台地址、反代入口、内部服务地址需由用户确认是否公开；不自行判断为必须保留。

## 导出前检查

- 一页约束是否满足；
- 是否出现两行孤立标题、被裁切照片、项目链接折断；
- 黑灰打印时层级是否仍清楚；
- 是否存在无意义的蓝色线条、图标或大面积填充；
- Word 与 PDF 中照片相对标题区是否一致。
- 与用户认可母版相比，是否出现明显古怪变化：照片变小/变形、页眉不协调、蓝色线条过多、空白异常、正文密度忽大忽小。
